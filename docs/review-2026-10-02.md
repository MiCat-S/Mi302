## 1. 總體結論

**一、多語言。** Wiki 確實是完整三語（12 個主題 × 繁體、簡體、英文，外加三語合一的 Home、_Sidebar、_Footer），README 也有三份；但這只是**文件翻譯**。管理介面只有繁體，程式裡沒有任何國際化機制（沒有字典、沒有語言切換、不看瀏覽器語言、設定檔沒有語言鍵），而文件自己就寫明「管理頁面只有繁體中文」。所以這不是漏做的功能，而是目前的設計範圍。要做多語言，難的不在翻譯：後端把中文句子直接當錯誤和狀態回給前端、前端靠比對中文字判斷狀態、確認字「清空」「取消訂閱」是 API 的一部分，這些都要先改成固定代碼。

**二、MoviePilot 相容性。** Mi302 呼叫的 17 個 MoviePilot API，路徑、方法、參數名、回傳結構都和實際跑的 v3.0.10-1 相符，主要讀取路徑已在主機上實測。不相符的有三處：

1. 補全缺集會替「TMDB 根本沒有的季」建訂閱，MoviePilot 每次都拒絕。目前版本仍在發生，日誌自 9/29 起累計 86 次。
2. Mi302 和 Wiki 都說「訂閱、整理只接受帳號登入」，但 v3.0.10-1 只帶 API 令牌就能通過認證。
3. MoviePilot 把 Mi302 當 Emby 用時會呼叫 `/emby/Users/Query`，Mi302 沒有實作，MoviePilot 日誌因此有 17 次 ERROR。

另外，外掛用到 MoviePilot 兩個雙底線私有方法，現在能用，但升級時容易壞。

**三、頁面功能。** 名字相近的功能（多個掃描入口、7 條刪除路徑、重複檔案／整理 115／reorganize、檢查缺集／補全）實際做的事不同，**不建議整體合併**，適合統一的是底層的刪除服務和導覽命名。真正的缺口集中在長任務和資料安全：

- 好幾個長任務停不下來，排隊中的掃描也停不掉。
- 重新啟動前的「忙碌」提示漏了 5 種工作。
- 刪媒體庫會連帶刪掉觀看紀錄，但對話框沒有說。
- 刪除紀錄只有「重複檔案」有。
- 改密碼不會讓舊登入失效。

**最重要的 5 個問題**

| # | 問題 | 優先 | 狀態 |
|---|---|---|---|
| 1 | 補全缺集替 TMDB 沒有的季建訂閱，次次失敗 | P1 | 【實機驗證】 |
| 2 | 刪除媒體庫會清掉該庫的觀看紀錄、續播點，提示只說「檔案不會被刪」 | P1 | 【代碼確認】 |
| 3 | 重新啟動／更新前的忙碌清單漏掉全部整理、檢查、取消訂閱、strm 改寫、中文名查詢 | P1 | 【代碼確認】 |

## 2. 問題清單（依優先序）

### P1-1 補全缺集：TMDB 沒有的季照樣建訂閱，MoviePilot 每次都拒絕

- **模組**：`embyserver/moviepilot.py`（MoviePilot →「補全缺集」）
- **現狀**：
  - `tmdb_episodes()` 把「查成功但清單是空的」也當成查不到，一律回傳 `None`（`moviepilot.py:650-660`，最後一行 `return episodes or None`）。
  - `_fill_season()` 遇到 `None` 時走「查不到 TMDB 集數，交給 MoviePilot 判斷」，照樣建訂閱（`moviepilot.py:961-967`）。
  - MoviePilot 對不存在的季回 `{"success": true, "data": []}`；建訂閱時又查不到該季總集數，回「未获取到第 N 季的总集数」。
- **證據**：
  - 【代碼確認】`moviepilot.py:644-660`、`:934-961`。
  - 【實機驗證】`GET /api/v1/tmdb/1399/99` 回 `{"success":true,"message":"","data":[]}`，`/tmdb/1399/1` 回 10 集。
  - 【實機驗證】Mi302 日誌自 9/29 起有 86 次「MoviePilot 不接受訂閱 …：未获取到第 N 季的总集数」（第 2 季 47、第 3 季 20、第 4 季 7、第 5 季 5、第 6 季 4、第 12 季 3）。10/02 02:23 那次補全（服務 02:20 以 `7ccca81` 重新啟動之後）又出現 4 次。
- **影響**：
  - 這些季永遠進不了「已訂閱」或「已送下載」，每次補全都重送、都記成失敗，錯誤清單被灌滿。
  - MoviePilot 每次都要重新辨識、查 TMDB。
  - 使用者看不出真正的原因：本機的季號和 TMDB 對不上，例如 TMDB 把多季合成一季，或用的是劇集組。
- **建議**：
  1. `tmdb_episodes()` 區分三種結果：連不上或出錯回 `None`；查成功但空的回 `{}`，並寫進 `tmdb_seasons`，讓 6 小時快取也記得「沒有這季」；有集數照舊。
  2. `_fill_season()` 遇到 `{}` 時新增一個 `absent` 計數，寫明細「TMDB 沒有第 N 季（季號可能和 TMDB 不同，到 115 網盤 → 整理 115 網盤 修正）」，不建訂閱。
  3. 清單的 `state` 加「季號對不上」，歸到「還沒對照」以外的分頁，按鈕導到「整理 115 網盤」並帶上搜尋字。
  4. 測試：`tests/test_fill.py` 的 FakeMP 加一個回空清單的季，斷言沒有送出 `POST /subscribe/`，`absent` 為 1。
- **驗證狀態**：【實機驗證】（現象與 MoviePilot 回應）＋【代碼確認】（原因）。

### P1-2 刪除媒體庫會清掉觀看紀錄，提示沒有說

- **頁面**：媒體庫 → 編輯 → 刪除媒體庫
- **現狀**：
  - 對話框只寫「資料夾裡的檔案不會被刪」（`admin.html:1406-1409`）。
  - 儲存後掃描時，`_drop_removed_libraries()` 刪掉該庫所有項目（`scanner.py:535-541`），`_after_delete()` 接著刪掉所有對不到項目的 `user_data`（`scanner.py:470-472`）。
  - 重新加回同一個資料夾會產生新的項目 id，看過的紀錄和續播點都回不來。
- **影響**：誤刪或為了「重建」媒體庫而刪掉再加回時，全家的觀看紀錄一起消失，而且無法復原（備份要停服務手動換檔）。
- **建議**（擇一或並用）：
  1. 最小改動：對話框寫明「這個媒體庫裡的觀看紀錄、續播點也會一起刪除」，並顯示筆數（新增一個 GET 回傳該庫 `user_data` 筆數）。
  2. 較完整：刪除前把該庫的 `user_data` 依**檔案路徑**存進保留表（例如 30 天）；掃描新增項目時，同路徑的就接回。這和 `dupes.py:812-835` 把紀錄搬到保留檔案的作法同一類。
  3. 測試加在既有的掃描測試：刪庫、加回、斷言紀錄還在（若採方案 2）。
- **驗證狀態**：【代碼確認】

### P1-3 重新啟動／更新前的「忙碌」清單漏了 5 種工作

- **頁面**：側欄「重新啟動」、版本對話框「更新」
- **現狀**：`_busy()` 只看 8 個旗標（`routes/web/server.py:15-24`）。漏掉的有：
  - **全部整理**（`organizer.batch.running`）。它每個資料夾用自己的區域 `ReorgJob()`（`organize115.py:1156-1158`），所以清單裡的「MoviePilot 整理」（`reorganizer.job.running`）在批次期間一直是 False。
  - **問 MoviePilot 檢查**（`organizer.job.running`，`organize115.py:441, 522`）。
  - **取消所有訂閱**（`moviepilot.unsubscribe_result.running`）。
  - **strm 改寫**（`strm_sync.rewrite_result.running`，`strm_sync.py:449`）。
  - **查中文名**（`person_names.running`，`people.py:306`）。
- **影響**：批次整理或取消訂閱跑到一半時按重新啟動，確認框說沒有工作在跑，結果整批中斷：批次結果、從「瀏覽 115」加入的清單（只在記憶體，見 P3-6）都會遺失。
- **建議**：把上面 5 個旗標加進 `_busy()`；在現有測試裡斷言批次整理期間 `GET /web/api/server` 的 `busy` 包含「全部整理」。
- **驗證狀態**：【代碼確認】

### P2-1 Mi302 認為「訂閱、整理只接受帳號登入」，v3.0.10-1 其實接受 API 令牌

- **模組**：`moviepilot.py`、`organize115.py`、`reorganize.py`；Wiki `MoviePilot*.md`
- **現狀**：
  - `can_subscribe` 要求帳號密碼（`moviepilot.py:631-634`）。它擋住了：補全缺集（`:855`）、取消所有訂閱（`:1095`）、清單的「已訂閱／已送下載」標記（`:1031`、`:1056`）、整理的檢查（`organize115.py:515`）、集數模板推薦（`organize115.py:1225`）、整理執行（`reorganize.py:145`、`routes/web/moviepilot.py:117`、`:159`），以及全量同步後自動補全（`app.py:77`）。
  - Wiki 寫「subscription API only accepts a logged-in account, not the API token」（`docs/wiki/MoviePilot.md:48-49`、`:218`，簡繁版本同義）。
- **上游**：
  - v3.0.10-1 的 `verify_token` 依序接受 JWT、`X-API-KEY`／`apikey`、`token`，API 金鑰對應到超級管理員身份（[`app/adapters/web/security/access.py#L265-L291`](https://github.com/jxxghp/MoviePilot/blob/v3.0.10-1/app/adapters/web/security/access.py#L265-L291)）。
  - `get_current_active_user*`、`get_current_active_manage_user`、`get_current_active_superuser*` 都建立在 `verify_token` 之上（[`app/api/dependencies/auth.py#L64-L165`](https://github.com/jxxghp/MoviePilot/blob/v3.0.10-1/app/api/dependencies/auth.py#L64-L165)）。
- **實測**（只帶 `X-API-KEY`）：

| 端點 | 正確令牌 | 錯誤令牌 |
|---|---|---|
| GET `/subscribe/`、`/subscribe/history/电视剧`、`/system/env`、`/storage/directories` | 200 | — |
| POST `/subscribe/`、`/transfer/manual`、`/transfer/episode-format/recommend`、`/transfer/manual/history`（送非法內容） | 422（認證已過，參數錯） | 401「apikey 校验不通过」 |

- **影響**：只設 API 令牌的使用者（Wiki 的建議設定）用不了補全缺集和整理 115，而且看到的說明是錯的。使用者自己的主機兩者都填了，所以目前沒有受影響。
- **建議**：
  1. 把 `can_subscribe` 改成「能力判斷」：有帳號密碼，或 `GET /system/env` 用令牌成功且版本 ≥ v3.0.0 即視為可用。結果和 `check_transfer_preview()` 一樣快取 10 分鐘。
  2. 401/403 且沒有帳號時，提示改成「這個 MoviePilot 版本不接受 API 令牌，請填帳號密碼」。
  3. 三種語言的 Wiki 改寫「只接受帳號登入」的段落，改成「V3 用 API 令牌即可；舊版需要帳號」。
  4. `tests/test_fill.py`、`tests/test_organize115.py` 的 FakeMP 目前沒有 Bearer 就回 401/403（`test_fill.py:101-102`、`test_organize115.py:185-186`）。加一個「接受 X-API-KEY」的模式驗證新判斷。
- **驗證狀態**：【實機驗證】（認證）；真的建訂閱、真的整理的回應屬【外部環境未驗證】（依使用者規則不在主機上操作整理）。

### P2-2 MoviePilot 把 Mi302 當 Emby 用：`/emby/Users/Query` 沒有實作

- **模組**：`embyserver/routes/system.py`、`routes/items.py`
- **現狀**：
  - MoviePilot 的媒體伺服器設定裡有一台 `emby` 指向 Mi302 並已啟用【實機驗證】。
  - MoviePilot Emby 模組會呼叫 `/emby/Users/Query`（取使用者數，[`app/modules/emby/emby.py#L301-L320`](https://github.com/jxxghp/MoviePilot/blob/v3.0.10-1/app/modules/emby/emby.py#L301-L320)）和 `/emby/Items/{id}/RemoteImages`（webhook 通知找 TMDB 圖，[`#L572-L595`](https://github.com/jxxghp/MoviePilot/blob/v3.0.10-1/app/modules/emby/emby.py#L572-L595)）。
  - Mi302 兩個都沒有路由；其他它用到的端點都有（`items.py:117-192`、`system.py:54,108,174,261`）。
- **證據**：【實機驗證】MoviePilot 日誌有 17 次 `【ERROR】… emby.py - Users/Query 未获取到返回数据`，是 Emby 模組唯一反覆出現的錯誤。RemoteImages 有退路（改用本機圖片連結），日誌沒有錯誤。
- **影響**：MoviePilot 儀表板的使用者數是 0，ERROR 日誌干擾排錯；功能本身不受影響。
- **建議**：
  - 加 `GET /users/query`，回 `{"Items": [...同 /users...], "TotalRecordCount": n}`。
  - 加 `GET /items/{id}/remoteimages`，回 `{"Images": [], "TotalRecordCount": 0, "Providers": []}`。
  - 在 `tests/test_moviepilot.py:169-197` 那組「MoviePilot 用到的 Emby 端點」測試裡加兩個斷言。
- **驗證狀態**：【實機驗證】

### 3.4 介面缺語言選擇的直接原因

1. **文字寫死在單一檔案**：`admin.html` 3,853 行中約 1,181 行含中文。靜態 HTML 約 556 段文字和屬性（168 個按鈕、54 個 option、50 個 aria-label、31 個 placeholder、28 個 title）；JS 約 930 個中文字串（54 個 `toast()`、29 個 `ask()`）。
2. **後端回的是中文句子，不是錯誤碼**：
   - `HTTPException` 一律以純文字回傳 `detail`（`app.py:211-214`），未預期錯誤回「伺服器錯誤：…」（`app.py:222-227`）。
   - 前端 `api()` 把回應文字原樣變成錯誤（`admin.html:984`），再用 `toast(e.message)` 顯示。
   - 後端約 70 個中文字面的 `HTTPException`、約 30 個轉傳模組例外、174 個模組裡的中文 `raise`；狀態、進度欄位也是中文（例如 `updater.py:303-338` 的 `step`）。
3. **前端靠比對中文判斷狀態**：`admin.html:1198` 的 `r.text.includes('沒有開啟')` 要和 `routes/dav.py:31` 的文字一致。
4. **確認字是 API 契約**：清空回收站要送「清空」（`routes/web/p115.py:137-138` ↔ `admin.html:3354-3358`），取消訂閱要送「取消訂閱」（`routes/web/moviepilot.py:153`、`:180` ↔ `admin.html:2625-2631`）。
5. **上游原文直接透出**：115 和 MoviePilot 的簡體訊息原樣接在繁體句子裡（例如 `p115.py:184-188` 熔斷原因、`moviepilot.py:683` 訂閱訊息），程式還要比對簡體關鍵字（`p115.py:95-97`、`organize115.py:1268-1269`）。換語言不只改介面，這些比對也要保留。
6. **測試綁死中文訊息**：`tests/` 約 543 行斷言含中文（`test_organize115.py` 116 行）。

| 2 | 前端字典 | `admin.html` 加 `I18N = {"zh-Hant": {...}, "zh-Hans": {...}, "en": {...}}` 和 `t(key, args)`；靜態 HTML 用 `data-i18n` 屬性，啟動時套用 | 單檔架構可以不引入建置工具 |

| 4 | 簡體 | 用 zhconv 產生初稿再人工改成大陸用語（Wiki 的簡體頁就是這樣做的） | 工作量最小 |
| 5 | 英文 | 可以沿用英文 Wiki 已有的譯名（Wiki 裡每個按鈕都有英文名） | |
| 6 | 測試 | `test_admin_page.py` 檢查三份字典的鍵一致、HTML 裡每個 `data-i18n` 都有鍵；`test_docs.py` 順便檢查每個主題三語都存在 | |
