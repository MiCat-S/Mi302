这一页写给想了解内部运作或参与开发的人：请求流程、路径怎么匹配、已实现的 Emby 接口、管理 API、代码结构、怎么运行测试，以及参考过的项目。

## 请求流程

Mi302 是一个 FastAPI 程序，用 uvicorn 运行，数据存在 SQLite（`data/library.db`）。

1. **扫描**：把媒体库文件夹里的 `.strm`、普通视频文件、nfo、图片写进数据库，见 [媒体库与扫描](媒体库与扫描)。
2. **浏览**：播放器调用 Emby API（`/Users/{id}/Views`、`/Items`…），Mi302 从数据库组装出 Emby 的 `BaseItemDto`。
3. **播放信息**：`POST /Items/{id}/PlaybackInfo`。strm 项目返回 `Protocol=Http`、`IsRemote=true`，只允许直接播放（关闭转码），`DirectStreamUrl` 指回 `/videos/{id}/stream.{格式}`。
4. **串流**：播放器请求 `/Videos/{id}/stream`、`/Videos/{id}/original.xxx` 或 `/Items/{id}/Download`：
   - strm 项目：读取 strm 内容，应用路径替换；带 pickcode 就用播放器的 User-Agent 向 115 获取直链，否则可以先跟随上游的重定向；最后返回 `302 Location: <真实地址>`。
   - 普通视频文件：直接发送文件，支持 Range。
5. **进度**：`/Sessions/Playing…` 记录续播位置和已看，也用来学习片头片尾，见 [片头片尾跳过](片头片尾跳过)。

细节见 [播放与外网访问](播放与外网访问)。Mi302 对外报告自己是 Emby Server 4.8.11.0。

## 路径和参数

每个进来的 HTTP 请求先整理路径，再匹配路由：

- 路径里的英文字母转成小写，其他字符不动（`/Persons/Émilie` 的 `É` 保留），所以路径不区分大小写。
- 去掉开头的 `/emby`、`/mediabrowser`，有没有这个前缀都可以。
- 去掉结尾的 `/`。
- 查询参数的名称不区分大小写（`ParentId`、`parentid` 都可以）。

其他：

- 错误响应是纯文本，和 Emby 一样。
- CORS 全开。
- FastAPI 自动生成的 API 文档在 `/api-docs`。

## 认证

token 依次从这些地方查找：

1. 请求头 `X-Emby-Token`、`X-MediaBrowser-Token`。
2. 请求头 `X-Emby-Authorization`（或 `Authorization`）里的 `Token="…"`，格式是 `MediaBrowser Client="…", Device="…", DeviceId="…", Version="…", Token="…"`。
3. 查询参数 `api_key`、`X-Emby-Token`、`ApiKey`、`X-MediaBrowser-Token`。

token 由 `POST /Users/AuthenticateByName` 签发。同一个用户在同一台设备（`DeviceId`）重新登录时，旧的 token 作废。API 密钥（配置文件的 `api_keys`，或在网页上创建的）以管理员的身份运行（按名称排序的第一个管理员），给 MoviePilot 这类程序用；它不能调用 `/web/api/…` 和 `/p115/…`。

路径里有用户（`/Users/{id}/…`）或带 `UserId` 参数时，读写的是那个人的观看记录、续播点和收藏。普通用户只能指定自己，指定别人返回 403；管理员和 API 密钥可以指定别人，找不到那个人返回 404。id 不区分大小写，也接受带连字符的 GUID 写法。没指定就是登录的人。

## 已实现的 Emby 接口

路径按 Emby 的写法列出，实际上不区分大小写。除了标注“不用登录”的，都要带 token。

`SortBy` 支持：`SortName`、`Name`、`DateCreated`、`DateLastContentAdded`、`PremiereDate`、`ProductionYear`、`CommunityRating`、`CriticRating`、`Runtime`、`Random`、`DatePlayed`、`PlayCount`、`IndexNumber`、`ParentIndexNumber`、`AiredEpisodeOrder`。

## 管理 API

管理页面 `/web` 用的 API。115 的文件、文件夹 id 有 19 位，超过 JavaScript 能精确表示的整数，返回时一律是字符串；传进来时字符串、数字都接受。除了 `/web/api/setup`，都要用管理员账号登录后的 token（放在 `X-Emby-Token` 请求头），API 密钥不行。请求和响应都是 JSON。

| 路径 | 用途 |
| --- | --- |
| `GET, POST /web/api/setup` | 是否需要创建第一个管理员；创建它（只在还没有任何账号时可用） |
| `GET, PUT /web/api/settings` | 读取、保存网页上的设置（写进配置文件） |
| `GET, POST /web/api/scan` | 扫描进度和各媒体库的项目数；开始扫描：`{"library": 名称}`、`{"path": 路径}`，都没有就扫描全部 |
| `GET, POST /web/api/users`；`PUT, DELETE /web/api/users/{id}` | 用户 |
| `GET /web/api/browse`、`/web/api/115/browse` | 选择服务器上的文件夹、选择 115 目录 |
| `GET /web/api/115/offline`、`POST /web/api/115/offline`、`POST /web/api/115/offline/delete`、`POST /web/api/115/offline/clear` | 115 云下载：任务列表（`page`，附这个月还能加几个）；加任务（`urls` 一行一个、`folder` 存到的 115 路径，空的用 115 默认）；删任务（`hashes`，`files` 连下载好的文件一起删）；清除已完成或已失败的记录（`what`：`done`／`failed`） |
| `POST /web/api/115/offline/retry` | 重新加入失败的云下载任务（`hash`、`url`、`folder_id`）：先删那一条失败的记录（不删文件），再加回原来的文件夹 |
| `GET /web/api/115/recyclebin`、`POST /web/api/115/recyclebin/clean` | 115 回收站的一页（`offset`、`limit`）；清空（永久删除，要 `{"confirm": "清空"}`，cookie 通道再带 `password` 安全密钥） |

| `POST /web/api/115/organize/folder`、`DELETE /web/api/115/organize/folder/{id}` | 浏览 115 里挑的文件夹（`cid`、`path`）固定在清单最上面；拿掉 |
| `POST /web/api/115/organize/preview`、`POST /web/api/115/organize/recommend`、`POST /web/api/115/organize/execute` | 预览一个文件夹（`id`；每一部分可以指定 `parts: {部分: {type, tmdbid, season, format}}`；`target` 是 `parent`／`auto`／`path` 加 `target_path`），返回预览代码 `token`；一部分的集数定位（`id`、`part`，先请 MoviePilot 推荐）；按预览代码执行（`tokens`，`cleanup` 整理完把没有视频留下的来源文件夹移到回收站） |
| `POST /web/api/115/organize/all`、`POST /web/api/115/organize/all/stop`、`GET /web/api/115/organize/all` | 全部整理：清单上符合 `q`、`kind` 的（加上浏览 115 固定上来的）在后台一个一个预览，没问题（预览的 `review` 是空的）就按预览整理，其他跳过并记原因（`target`、`target_path`、`cleanup`；标记了先不整理的、一次要送超过 `max_videos` 支视频的不做，默认 300，0 = 不限；MoviePilot 连不上时等它恢复，最多 15 分钟）；做完手上这一个就停；进度和跳过、失败的明细（明细最多留 2000 个，`results_total` 是全部的数量，`truncated` 表示有没有留不下的；进度也在 `GET /web/api/115/organize/job` 的 `batch`） |
| `POST /web/api/115/organize/hold` | 先不整理（`id`、`hold`）：全部整理时跳过、排到清单后面；返回那一个 |
| `GET /web/api/115/organize/episodes`、`POST /web/api/115/organize/delete` | 删除：一部剧的每一集和剧集文件夹（`series`，集号不对的标 `problem`）；删勾选的集（`series_id`、`file_ids`、`remove_folder`），或清单上的一个整个删（`id`），都移到 115 回收站，本地 strm 和媒体库跟着拿掉 |

## 开发和测试

需要 Python 3.10 以上。在 venv 里：

```bash
pip install -r requirements.txt pytest ruff
python -m pytest
ruff check embyserver tests
```

测试也会用 `node --check` 检查管理页面的 JavaScript 语法（没有 node 就跳过），并检查文档：Wiki 的链接和锚点都找得到、每一页都在侧栏、三种语言的配置文件参考都写到每一个键。

改了 `install.sh` 之后：

```bash
shellcheck install.sh
```

- [DDSRem-Dev/MoviePilot-Plugins](https://github.com/DDSRem-Dev/MoviePilot-Plugins)：302 播放流程参考 `embyreverseproxy` 插件，区别是 Mi302 背后不需要真的 Emby，Emby API 自己实现；115 扫码登录和获取直链的流程参考 `p115strmhelper`。
