本页说明 Mi302 如何取得视频的媒体信息（分辨率、HDR、音轨、字幕轨、章节）：读取视频旁边现成的 `X-mediainfo.json`，或自己用 ffprobe 探测，以及探测时如何避免触发 115 的限流。

## 为什么需要媒体信息

播放器要知道视频的分辨率、HDR／杜比视界、音轨、内封字幕和章节，才能在列表上标出 4K、HDR，播放前让人选择音轨和字幕。strm 只是一行网址，这些信息不在里面，要另外从视频的文件头读出来。

没有媒体信息时，Mi302 返回给播放器的媒体流列表是空的。视频照样能播，只是看不到这些标示和选项。

有媒体信息的视频，Mi302 返回给播放器的内容多了这些：

- 媒体流：视频、音轨、字幕轨（含语言、标题、是否默认、是否强制）和附件。
- 容器格式、分辨率、有没有字幕、默认音轨。
- 码率、文件大小、片长：原本没有时才补上。nfo 没写片长时，也用它的片长。
- 章节。学到的片头片尾标记会加在章节后面，见[片头片尾跳过](片头片尾跳过)。

播放方式不变：仍然 302 到 115 直链，不转码。

## X-mediainfo.json

视频是 `X.strm`（或本地视频 `X.mkv`）时，Mi302 读取同一个文件夹里的 `X-mediainfo.json`。格式和 Emby 神医助手（[StrmAssistant](https://github.com/sjtuross/StrmAssistant)）的“媒体信息持久化”一样：

```json
[{"MediaSourceInfo": {"Container": "mkv", "MediaStreams": [...]}, "Chapters": [...]}]
```

- 用过 Emby＋神医，或用 [emby-mediainfo](https://github.com/xiao-vvv/emby-mediainfo) 生成过的文件，放在 strm 旁边就能用。
- 扫描时读进来，另外在 Mi302 的数据库里存一份。json 的修改时间变了，下次扫描会重新读取。
- 反过来，Mi302 探测写出的 json，Emby＋神医那边也能读。
- 神医设置了“媒体信息根目录”（json 集中放在另一个文件夹）时，Mi302 找不到，要把文件移到 strm 旁边。
- 同步时 115 上的视频改名、移动、删除，本地的 `X-mediainfo.json` 跟着 strm 一起改名、移动、删除。
- 超过 8 MB 或格式不对的 json 会跳过，日志里有警告。

## 用 ffprobe 探测

没有现成 json 的视频，Mi302 可以自己用 ffprobe 探测。设置在“媒体库”页的“媒体资讯”卡片。有两种方式，可以同时开启。

### 打开时自动探测

“打开影片时自动探测”默认开启。播放器打开某部电影或某一集（查看详情或准备播放）时，如果这一项还没有媒体信息，就排进后台队列。请求照常立即响应，不等探测；下次打开就有了。

- 只排被打开的 strm 项目。浏览列表不会触发，一次打开整季也不会把整季排进去。
- 队列最多 500 项，满了的下次打开再排。
- 探测失败或被跳过的项目，一小时内不再排。
- 遇到 115 限流、还没登录 115、找不到 ffprobe 这类后面也不会成功的错误，整个队列清空，这些项目一小时后打开再排。

不想整库探测的话，开这个就够了：常看的片会慢慢有媒体信息。

### 整库探测

“整库探测”默认关闭。开启并点卡片下方的“储存”后：

- 可以点卡片右上角的“提取缺少的媒体资讯”，把媒体库里还没有媒体信息的视频（strm 和本地视频）全部探测一遍，新的视频先做。同一时间只运行一批，已经在运行时再点会提示“已经在探测中”。
- “同步产生新的 strm 后自动探测”默认勾选，要开启整库探测才有作用。勾选时，每次同步新生成的 strm，以及 115 上换了文件的 strm（见下文），会在后台探测。探测和扫描、刮削同时进行，互不等待。

### 探测一项时做了什么

1. 读取 strm 的内容（先套用 `redirect.path_rules`）。
2. 是 115 的 strm 时，向 115 取一次直链。取直链和 ffprobe 用同一个普通浏览器的 User-Agent（115 的直链绑定 UA），ffprobe 读文件时复用同一条连接，减少触发 115 CDN 的限流。
3. strm 里是其他网址（例如 alist）时，ffprobe 直接读那个网址；是本地路径、或本身就是本地视频时，读本地文件。这两种不向 115 取直链，也不计入每小时上限。
4. ffprobe 只读文件头，通常几 MB。
5. 结果写成 `X-mediainfo.json` 放在 strm 旁边，也存进数据库。视频里有章节就用视频的；没有章节时和 Emby 一样每 5 分钟生成一个。媒体文件夹只读、写不进去时，只存在数据库里。
6. 视频原本没有片长时，补上探测到的片长。

每一项最多等 `mediainfo.timeout` 秒（默认 300），超过算失败。

## 设置

| 页面上的名称 | 配置键 | 默认值 | 范围 |
|---|---|---|---|
| 打开影片时自动探测 | `mediainfo.on_demand` | 开 | |
| 整库探测 | `mediainfo.enabled` | 关 | |
| 同步产生新的 strm 后自动探测 | `mediainfo.after_sync` | 开 | 要开启整库探测 |
| 同时探测几项 | `mediainfo.concurrency` | 2 | 1–3 |
| 取直链间隔（秒） | `mediainfo.interval` | 1.0 | 0.5–60 |
| 每小时最多几次 | `mediainfo.hourly_limit` | 300 | 0–100000，0 = 不限 |
| （只在配置文件） | `mediainfo.timeout` | 300 | 10–3600 秒 |
| （只在配置文件） | `mediainfo.ffprobe` | `ffprobe` | ffprobe 的路径 |

在页面上改完点卡片下方的“储存”，立即生效，不必重启。配置文件的写法见[配置文件参考](配置文件参考)。

## 115 的限制

每一项 115 的 strm 都要向 115 取一次直链。115 对此很敏感，Mi302 这样保护账号：

- **同时几条连接**：115 同时最多 3 条连接，所以“同时探测几项”最多 3，默认 2。
- **取直链间隔**：两次取直链之间至少隔 0.5 秒，默认 1 秒。所有探测共用这个间隔。
- **每小时上限**：默认每小时最多 300 次，0 = 不限。到了上限，就等最早的那次满一小时再继续。第一次整库探测上万个视频时，会分几天慢慢补齐。
- **熔断**：115 返回限流或登录失效时，探测和同步都先停下，这一批剩下的不做。限流造成的熔断 45 分钟后自动解除；登录失效要到“115 网盘”页重新“扫码登入”。中断的整库探测不会自己重新运行，熔断解除后再点一次“提取缺少的媒体资讯”；熔断期间点了也会马上停下。冷却期满后的前 30 分钟，间隔变为 4 倍、每小时上限变为四分之一；再往后 30 分钟是 2 倍和一半；之后恢复正常。

打开即探测和整库探测共用间隔、每小时上限和熔断。播放不受这些限制，也不受熔断影响。熔断的原因会显示在“媒体资讯”卡片和“115 网盘”页。熔断的细节见[115 网盘与同步](115-网盘与同步)。

## 115 上的文件换了

同步时如果 115 上同一个位置的文件被换掉（例如换成另一个版本），它的 pickcode 会变。pickcode 是 115 给每个文件的提取码，strm 靠它取直链。这时旧的媒体信息属于另一个文件，Mi302 会删掉 `X-mediainfo.json` 和数据库里的记录：

- 开启了整库探测和“同步产生新的 strm 后自动探测”时，同步完就重新探测。
- 否则等下次打开这一项时自动探测，或点“提取缺少的媒体资讯”。

只改服务器网址（`p115.strm.base_url`）或 strm 网址格式而重写的 strm，pickcode 没变，媒体信息照用。

## 卡片上能看到什么

“媒体资讯”卡片显示：

- “N / M 支影片有媒体资讯”。
- 找不到 ffprobe 时的警告；115 熔断时的原因。
- 打开即探测的队列：排队中、完成、失败各几项。
- 这一小时向 115 取了几次直链、上限多少；熔断刚恢复时放慢几倍；到了上限时，几点后继续。
- 上次整库探测（同步后自动或手动）的结果：要探测、成功、失败、跳过，以及前几个失败原因。

失败和跳过的原因：

- **跳过**：strm 是空的；strm 里不是网址，也不是存在的文件。
- **整批停下**：找不到 ffprobe、还没登录 115、115 熔断。停下后还没做的算失败。
- **单项失败**：ffprobe 读不了（例如 403、超时、解码错误）、超过每一项的等待时间、没有读到任何流。错误信息里的网址会抹掉，再写进卡片和日志。

失败的视频仍然没有媒体信息，下次点“提取缺少的媒体资讯”会重试。

## 安装 ffmpeg

ffprobe 是 ffmpeg 的一部分。

- 一键安装脚本在安装和 `mi302 update` 时，会用系统的包管理器（apt、dnf、yum、apk、pacman、zypper、brew）尝试安装 ffmpeg。没装成只会警告，其他功能不受影响。见[安装](安装)。
- 自己安装：

```bash
sudo apt install ffmpeg   # Debian／Ubuntu
brew install ffmpeg       # macOS
```

- 装好后不必重启，Mi302 一分钟内会找到 ffprobe。
- ffprobe 不在服务的 PATH 里时，在配置文件里把 `mediainfo.ffprobe` 填成完整路径。

没有 ffprobe 时，Mi302 仍会读取现成的 `X-mediainfo.json`。卡片会显示警告，“提取缺少的媒体资讯”点不了，打开即探测和同步后探测都不做。
