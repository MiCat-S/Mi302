這一頁說明 Mi302 怎麼取得影片的媒體資訊（解析度、HDR、音軌、字幕軌、章節）：讀影片旁邊現成的 `X-mediainfo.json`，或自己用 ffprobe 探測，以及探測時怎麼避免觸發 115 的限流。

## 為什麼需要媒體資訊

播放器要知道影片的解析度、HDR／杜比視界、音軌、內封字幕和章節，才能在列表上標出 4K、HDR，播放前讓人選音軌和字幕。strm 只是一行網址，這些資訊不在裡面，要另外從影片的檔頭讀出來。

沒有媒體資訊時，Mi302 回給播放器的媒體流清單是空的。影片照樣能播，只是看不到這些標示和選項。

有媒體資訊的影片，Mi302 回給播放器的內容多了這些：

- 媒體流：影片、音軌、字幕軌（含語言、標題、是否預設、是否強制）和附件。
- 容器格式、解析度、有沒有字幕、預設音軌。
- 碼率、檔案大小、片長：原本沒有時才補上。nfo 沒寫片長時，也用它的片長。
- 章節。學到的片頭片尾標記會加在章節後面，見[片頭片尾跳過](片頭片尾跳過)。

播放方式不變：仍然 302 到 115 直鏈，不轉碼。

## X-mediainfo.json

影片是 `X.strm`（或本機影片 `X.mkv`）時，Mi302 讀同一個資料夾裡的 `X-mediainfo.json`。格式和 Emby 神醫助手（[StrmAssistant](https://github.com/sjtuross/StrmAssistant)）的「媒體資訊持久化」一樣：

```json
[{"MediaSourceInfo": {"Container": "mkv", "MediaStreams": [...]}, "Chapters": [...]}]
```

- 用過 Emby＋神醫，或用 [emby-mediainfo](https://github.com/xiao-vvv/emby-mediainfo) 產生過的檔案，放在 strm 旁邊就能用。
- 掃描時讀進來，另外存一份在 Mi302 的資料庫。json 的修改時間變了，下次掃描會重新讀。
- 反過來，Mi302 探測寫出的 json，Emby＋神醫那邊也讀得懂。
- 神醫設定了「媒體資訊根目錄」（json 集中放在另一個資料夾）時，Mi302 找不到，要把檔案搬到 strm 旁邊。
- 同步時 115 上的影片改名、搬移、刪除，本機的 `X-mediainfo.json` 跟著 strm 一起改名、搬移、刪除。
- 超過 8 MB 或格式不對的 json 會略過，日誌裡有警告。

## 用 ffprobe 探測

沒有現成 json 的影片，Mi302 可以自己用 ffprobe 探測。設定在「媒體庫」分頁的「媒體資訊」卡片。有兩種方式，可以同時開。

### 打開影片時自動探測

「打開影片時自動探測」預設開啟。播放器打開某部電影或某一集（看詳情或準備播放）時，這一項如果還沒有媒體資訊，就排進背景佇列。請求照常馬上回應，不等探測；下次打開就有。

- 只排被打開的 strm 項目。瀏覽列表不會觸發，一次打開整季也不會把整季排進去。
- 佇列最多 500 項，滿了的下次打開再排。
- 探測失敗或略過的項目，一小時內不再排。
- 遇到 115 限流、還沒登入 115、找不到 ffprobe 這類後面也不會成功的錯誤，整個佇列清空，這些項目一小時後打開再排。

不想整庫探測的話，開這個就夠了：常看的片會慢慢有媒體資訊。

### 整庫探測

「整庫探測」預設關閉。開啟並按卡片下方的「儲存」後：

- 可以按卡片右上角的「提取缺少的媒體資訊」，把媒體庫裡還沒有媒體資訊的影片（strm 和本機影片）全部探測一次，新的影片先做。同一時間只跑一批，已經在跑時再按會提示「已經在探測中」。
- 「同步產生新的 strm 後自動探測」預設勾選，要開整庫探測才有作用。勾選時，每次同步新產生的 strm，以及 115 上換了檔案的 strm（見下方），會在背景探測。探測和掃描、刮削同時進行，互不等待。

### 探測一項時做了什麼

1. 讀 strm 的內容（先套用 `redirect.path_rules`）。
2. 是 115 的 strm 時，向 115 取一次直鏈。取直鏈和 ffprobe 用同一個一般瀏覽器的 User-Agent（115 的直鏈綁定 UA），ffprobe 讀檔時重用同一條連線，少觸發 115 CDN 的限流。
3. strm 裡是其他網址（例如 alist）時，ffprobe 直接讀那個網址；是本機路徑、或本身就是本機影片時，讀本機檔案。這兩種不向 115 取直鏈，也不算進每小時上限。
4. ffprobe 只讀檔頭，通常幾 MB。
5. 結果寫成 `X-mediainfo.json` 放在 strm 旁邊，也存進資料庫。影片裡有章節就用影片的；沒有章節時和 Emby 一樣每 5 分鐘產生一個。媒體資料夾唯讀、寫不進去時，只存在資料庫。
6. 影片原本沒有片長時，補上探測到的片長。

每一項最多等 `mediainfo.timeout` 秒（預設 300），超過算失敗。

## 設定

| 網頁上的名稱 | 設定鍵 | 預設值 | 範圍 |
|---|---|---|---|
| 打開影片時自動探測 | `mediainfo.on_demand` | 開 | |
| 整庫探測 | `mediainfo.enabled` | 關 | |
| 同步產生新的 strm 後自動探測 | `mediainfo.after_sync` | 開 | 要開整庫探測 |

| （只在設定檔） | `mediainfo.timeout` | 300 | 10–3600 秒 |

網頁上改完按卡片下方的「儲存」，立刻生效，不必重新啟動。設定檔的寫法見[設定檔參考](設定檔參考)。

## 115 的限制

每一項 115 的 strm 都要向 115 取一次直鏈。115 對這件事很敏感，Mi302 這樣保護帳號：

- **同時幾條連線**：115 同時最多 3 條連線，所以「同時探測幾項」最多 3，預設 2。
- **取直鏈間隔**：兩次取直鏈之間至少隔 0.5 秒，預設 1 秒。所有探測共用這個間隔。
- **每小時上限**：預設每小時最多 300 次，0 = 不限。到了上限，就等最早的那次滿一小時再繼續。第一次整庫探測上萬支影片時，會分幾天慢慢補齊。
- **熔斷**：115 回應限流或登入失效時，探測和同步都先停下，這一批剩下的不做。限流造成的熔斷 45 分鐘後自動解除；登入失效要到「115 網盤」分頁重新「掃碼登入」。中斷的整庫探測不會自己重跑，熔斷解除後再按一次「提取缺少的媒體資訊」；熔斷期間按了也會馬上停下。冷卻期滿後的前 30 分鐘，間隔變 4 倍、每小時上限變成四分之一；再來 30 分鐘是 2 倍和一半；之後恢復正常。

打開即探測和整庫探測共用間隔、每小時上限和熔斷。播放不受這些限制，也不受熔斷影響。熔斷的原因會顯示在「媒體資訊」卡片和「115 網盤」分頁。熔斷的細節見[115 網盤與同步](115-網盤與同步)。

## 115 上的檔案換了

同步時如果 115 上同一個位置的檔案被換掉（例如換成另一個版本），它的 pickcode 會變。pickcode 是 115 給每個檔案的提取碼，strm 靠它取直鏈。這時舊的媒體資訊是另一個檔案的，Mi302 會刪掉 `X-mediainfo.json` 和資料庫裡的紀錄：

- 開了整庫探測和「同步產生新的 strm 後自動探測」時，同步完就重新探測。
- 否則等下次打開這一項時自動探測，或按「提取缺少的媒體資訊」。

只改伺服器網址（`p115.strm.base_url`）或 strm 網址格式而重寫的 strm，pickcode 沒變，媒體資訊照用。

## 卡片上看得到什麼

「媒體資訊」卡片顯示：

- 「N / M 支影片有媒體資訊」。
- 找不到 ffprobe 時的警告；115 熔斷時的原因。
- 打開即探測的佇列：排隊中、完成、失敗各幾項。
- 這一小時向 115 取了幾次直鏈、上限多少；熔斷剛恢復時放慢幾倍；到了上限時，幾點後繼續。
- 上次整庫探測（同步後自動或手動）的結果：要探測、成功、失敗、略過，以及前幾個失敗原因。

失敗和略過的原因：

- **略過**：strm 是空的；strm 裡不是網址，也不是存在的檔案。
- **整批停下**：找不到 ffprobe、還沒登入 115、115 熔斷。停下後還沒做的算失敗。
- **單項失敗**：ffprobe 讀不了（例如 403、逾時、解碼錯誤）、超過每一項的等待時間、沒有讀到任何串流。錯誤訊息裡的網址會抹掉，才寫進卡片和日誌。

失敗的影片還是沒有媒體資訊，下次按「提取缺少的媒體資訊」會再試。

## 安裝 ffmpeg

ffprobe 是 ffmpeg 的一部分。

- 一鍵安裝腳本在安裝和 `mi302 update` 時，會用系統的套件管理員（apt、dnf、yum、apk、pacman、zypper、brew）試著裝 ffmpeg。沒裝成只會警告，其他功能不受影響。見[安裝](安裝)。
- 自己裝：

```bash
sudo apt install ffmpeg   # Debian／Ubuntu
brew install ffmpeg       # macOS
```

- 裝好後不必重新啟動，Mi302 一分鐘內會找到 ffprobe。
- ffprobe 不在服務的 PATH 裡時，在設定檔把 `mediainfo.ffprobe` 填成完整路徑。

沒有 ffprobe 時，Mi302 仍會讀現成的 `X-mediainfo.json`。卡片會顯示警告，「提取缺少的媒體資訊」按不了，打開即探測和同步後探測都不做。
