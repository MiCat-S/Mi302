這一頁列出設定檔 `config.yaml` 的每一個鍵：意思、預設值、允許的範圍、能不能在管理網頁上改，以及要不要重新啟動。平常在管理網頁上設定就好，不必直接改這個檔案。

## 設定檔在哪裡

| 安裝方式 | 位置 |
| --- | --- |
| 一鍵安裝（Linux） | `/opt/mi302/config/config.yaml` |
| 一鍵安裝（macOS） | `~/Mi302/config/config.yaml` |
| 手動用 Python | 執行指令時所在資料夾的 `config.yaml` |

啟動時可以用 `-c 路徑` 指定設定檔。沒指定時看環境變數 `EMBYSERVER_CONFIG`，再沒有就用目前資料夾的 `config.yaml`。「進階設定」頁最上面會顯示目前用的是哪個檔案。

## 設定檔怎麼運作

- **自動產生**：第一次啟動時沒有設定檔，Mi302 用預設值啟動，並產生一份附說明註解的設定檔。
- **網頁儲存時寫回**：在管理網頁上儲存設定時，檔案依範本整個重新產生，覆寫前把舊檔留成 `config.yaml.bak`。自己加的註解和不認得的鍵不會保留。
- **直接改檔案**：改完後打開或重新整理管理網頁，Mi302 發現檔案改過，就重新讀取並套用。
- **寫錯時**：啟動時設定檔格式錯誤（YAML 寫錯、少了必填的鍵），Mi302 不會啟動。原因印在啟動時的輸出，不在日誌檔裡：Linux 的服務用 `journalctl -u mi302` 看，macOS 和沒有 systemd 的環境在 `data/logs/console.log`，手動執行的在終端機上。執行中改壞了，網頁上方會顯示錯誤，Mi302 繼續用上次讀到的設定。
- **不認得的鍵**：打錯字或舊版留下的鍵會被略過，Mi302 記一筆警告「設定檔 … 底下不認得 …，已略過」，不影響啟動。

### 要重新啟動才生效的鍵

下面這些只在啟動時讀取，改了要重新啟動 Mi302（一鍵安裝的用 `mi302 restart`）：

- `server.host`、`server.port`、`server.data_dir`
- `users`
- `p115.cookies`、`p115.timeout`
- `redirect.resolve_timeout`

其他的鍵在網頁上儲存後馬上生效；直接改檔案的，重新整理管理網頁後生效。

### 檢查與範圍

在網頁上儲存，或重新讀取改過的設定檔時，Mi302 會檢查設定。有錯的不會套用，並顯示原因。超出範圍的數字會自動改成最接近的允許值：

| 鍵 | 允許的範圍 |
| --- | --- |
| `server.backup_keep` | 0–90 |
| `server.log_level` | `info` 或 `debug`，其他值當成 `info` |
| `moviepilot.concurrency` | 1–8 |
| `mediainfo.concurrency` | 1–3 |
| `mediainfo.interval` | 0.5–60 |
| `mediainfo.timeout` | 10–3600 |
| `mediainfo.hourly_limit` | 0–100000 |

其他檢查：

- 媒體庫：名稱不可空白、不可重複，至少要有一個資料夾。`type` 不是 `tvshows` 的一律當成 `movies`。
- 同步任務：115 目錄和本機資料夾都要填；本機資料夾要是完整路徑；兩個任務的本機資料夾不能相同或互相包含。
- `moviepilot.url` 要以 `http://` 或 `https://` 開頭，結尾的 `/` 會去掉。
- 路徑對應、路徑替換裡 `from` 或 `to` 空白的那一條會被略過。
- `mediainfo.ffprobe` 空白時當成 `ffprobe`。

## 不在設定檔裡的資料

這些存在資料庫 `<data_dir>/library.db`，不寫進設定檔，每天的備份會包含它們（見[備份與還原](備份與還原)）：

- 帳號和密碼（只存雜湊）。帳號建立之後，在網頁「使用者」分頁新增、改密碼、刪除，都不會寫回設定檔。
- 115 登入狀態：掃碼或貼上的 cookie，以及 115 開放平台的 token。
- 在網頁上建立的 API 金鑰。
- 115 同步的進度和對照表、自動偵測到的 strm 伺服器位址。
- 觀看紀錄、媒體資訊、學到的片頭片尾等。

## users

啟動時預先建立的帳號。預設是 `users: []`，平常留空就好：第一次打開管理網頁時，會請你建立管理員。

```yaml
users:
  - name: admin
    password: 你的密碼
    admin: true
```

| 鍵 | 預設值 | 說明 |
| --- | --- | --- |
| `name` | 必填 | 帳號名稱 |
| `password` | 空 | 密碼，明碼 |
| `admin` | `false` | 是否為管理員。管理員才能進管理網頁 |

- 只能改檔案，要重新啟動。
- 每次啟動時，清單裡還不存在的帳號會被建立。已經存在的帳號不會被改，所以在這裡改密碼沒有作用。
- 在網頁上刪掉的帳號，如果還留在這個清單裡，下次啟動會被重新建立。
- 密碼是明碼，`config.yaml.bak` 和備份的 `.yaml` 裡也有。帳號建好之後，可以把這段刪掉，帳號仍然在資料庫裡。

## libraries

媒體庫。預設是 `libraries: []`，在「媒體庫」分頁用「新增媒體庫」建立，按「儲存並掃描」。

```yaml
libraries:
  - name: 電影
    type: movies
    paths:
      - /media/movies
  - name: 劇集
    type: tvshows
    paths:
      - /media/tv
```

| 鍵 | 預設值 | 說明 |
| --- | --- | --- |
| `name` | 必填 | 媒體庫名稱，不可重複 |
| `type` | `movies` | `movies` = 電影，`tvshows` = 劇集 |
| `paths` | 必填 | 資料夾清單，至少一個。舊版的單一 `path` 也認得 |

改了媒體庫之後，只重新掃描有改的媒體庫；刪掉的媒體庫連同裡面的項目一起移除。見[媒體庫與掃描](媒體庫與掃描)。

## p115

115 網盤的登入。登入請用網頁掃碼，見 [115 網盤與同步](115-網盤與同步)。

| 鍵 | 預設值 | 說明 | 在網頁上改 |
| --- | --- | --- | --- |
| `cookies` | 空 | 115 cookie，效果等同在網頁上貼上 cookie。只在啟動時、而且資料庫裡還沒有 115 登入時使用。只能有英文字母、數字和符號，不能換行 | 只能改檔案，要重新啟動。網頁上貼的 cookie 存在資料庫，不寫進這裡 |
| `app` | `alipaymini` | 掃碼登入時佔用的 115 裝置類型，同類型的其他登入會被踢下線。可選 `alipaymini`、`wechatmini`、`tv`、`qandroid`、`ios`、`android`、`web` | 進階設定 → 115 與 strm →「掃碼登入佔用的 115 裝置類型」，下次掃碼時生效 |
| `timeout` | `15.0` | 呼叫 115 的逾時秒數 | 只能改檔案，要重新啟動 |
| `open_app_id` | 空 | 115 開放平台 AppID，只有自己申請到應用的人才需要 | 進階設定 → 115 與 strm →「115 開放平台 AppID」 |

## p115.strm

同步成 strm 的選項。「115 網盤」分頁的「同步選項」卡片改完按「儲存同步選項」；「進階設定」的欄位按頁面下方的「儲存設定」。

| 鍵 | 預設值 | 說明 | 在網頁上改 |
| --- | --- | --- | --- |
| `interval` | `0` | 每隔幾分鐘自動增量同步；0 = 不自動，建議 5 | 115 網盤 → 同步選項 →「自動增量同步間隔（分鐘）」 |
| `full_interval` | `168` | 每隔幾小時自動全量同步；0 = 不自動，168 = 每週 | 115 網盤 → 同步選項 →「自動全量同步間隔（小時）」 |
| `min_size_mb` | `0` | 小於這個大小（MB）的影片不產生 strm；0 = 不限 | 115 網盤 → 同步選項 →「略過小於這個大小的影片（MB）」 |
| `download_metadata` | `true` | 一併下載 115 上的 nfo、圖片、字幕 | 115 網盤 → 同步選項 →「一併下載 115 上的 nfo、海報、字幕」 |
| `delete_stale` | `false` | 115 上刪掉或移出同步目錄的影片，本機的 strm 和刮削資料也跟著刪 | 115 網盤 → 同步選項 →「跟著刪」 |
| `base_url` | 空 | strm 裡的伺服器網址；空 = 自動用開管理網頁時的網址 | 進階設定 → 115 與 strm →「strm 裡的伺服器網址」 |
| `include_name` | `false` | strm 網址後面附上 `?/原檔名`，方便人工辨識 | 進階設定 → 115 與 strm →「strm 網址後附上原檔名」 |
| `request_delay` | `0.2` | 逐層列 115 目錄、個別查資料夾路徑時，每次請求前等幾秒 | 進階設定 → 115 與 strm →「每列一個 115 目錄前等待的秒數」 |
| `scan_after_sync` | `true` | 同步完重新掃描有變動的地方 | 進階設定 → 115 與 strm →「同步完自動重新掃描媒體庫」 |
| `tasks` | `[]` | 同步任務，見下面 | 115 網盤 →「同步任務」 |

`interval`、`full_interval` 沒有上限，0 或負數都表示不自動。

`tasks` 的格式：

```yaml
p115:
  strm:
    tasks:
      - remote: /影視/電影
        local: /media/movies/115
```

- `remote`：115 上的目錄。開頭沒有 `/` 時會自動補上。
- `local`：放 strm 的本機資料夾，要是完整路徑，而且要在某個媒體庫裡。
- 兩個任務的 `local` 不能相同，也不能一個在另一個裡面。

## moviepilot

刮削交給 MoviePilot。見 [MoviePilot 整合](MoviePilot-整合)。

| 鍵 | 預設值 | 說明 | 在網頁上改 |
| --- | --- | --- | --- |
| `url` | 空 | MoviePilot 網址，例如 `http://192.168.1.10:3000`，要以 `http://` 或 `https://` 開頭 | MoviePilot → 連線 →「MoviePilot 網址」 |
| `api_token` | 空 | MoviePilot 的「設定 → 系統 → API 令牌」 | MoviePilot → 連線 →「API 令牌」 |
| `username` | 空 | MoviePilot 帳號。補全缺集（建訂閱）需要；舊版刮削 API 不接受令牌時也需要 | MoviePilot → 連線 →「MoviePilot 帳號」 |
| `password` | 空 | MoviePilot 密碼，明碼 | MoviePilot → 連線 →「MoviePilot 密碼」 |
| `scrape_after_sync` | `true` | 同步產生新的 strm 後自動送去刮削 | MoviePilot → 連線 →「同步產生新的 strm 後自動送去刮削」 |
| `fill_after_full_sync` | `false` | 全量同步後把所有有 tmdbid 的劇送給 MoviePilot 訂閱，補齊缺集 | MoviePilot → 補全缺集 →「全量同步後自動補全」 |
| `timeout` | `300` | 每一項刮削最多等幾秒 | 只能改檔案 |
| `concurrency` | `3` | 同時送幾項給 MoviePilot 刮削，1–8。太多可能被 TMDB 限速 | MoviePilot → 連線 →「同時刮削幾項」 |
| `path_mappings` | `[]` | 兩邊看到的路徑不同時：Mi302 的路徑（`from`）→ MoviePilot 的路徑（`to`） | MoviePilot → 連線 →「路徑對應」，一行一條 `Mi302 的路徑 => MoviePilot 的路徑` |

```yaml
moviepilot:
  path_mappings:
    - from: /media/psf/Vo
      to: /Volumes/Vo
```

## mediainfo

用 ffprobe 探測 strm 指向的影片，寫出 `X-mediainfo.json`。「媒體庫」分頁的「媒體資訊」卡片改完按「儲存」。見[媒體資訊與探測](媒體資訊與探測)。

| 鍵 | 預設值 | 說明 | 在網頁上改 |
| --- | --- | --- | --- |
| `enabled` | `false` | 整庫探測（手動按鈕、同步後自動）；關閉時仍會讀現成的 `X-mediainfo.json` | 媒體庫 → 媒體資訊 →「整庫探測」 |
| `after_sync` | `true` | 同步產生新的 strm 後自動探測，要開整庫探測 | 媒體庫 → 媒體資訊 →「同步產生新的 strm 後自動探測」 |
| `on_demand` | `true` | 播放器打開某部片或某一集時，在背景探測它 | 媒體庫 → 媒體資訊 →「打開影片時自動探測」 |
| `concurrency` | `2` | 同時探測幾項，1–3。115 同時最多 3 條連線 | 媒體庫 → 媒體資訊 →「同時探測幾項」 |
| `interval` | `1.0` | 每次向 115 取直鏈至少間隔幾秒，0.5–60 | 媒體庫 → 媒體資訊 →「取直鏈間隔（秒）」 |
| `hourly_limit` | `300` | 每小時最多向 115 取幾次直鏈，0 = 不限，最多 100000 | 媒體庫 → 媒體資訊 →「每小時最多幾次」 |
| `timeout` | `300` | 每一項最多等幾秒，10–3600 | 只能改檔案 |
| `ffprobe` | `ffprobe` | ffprobe 的路徑 | 只能改檔案 |

## redirect

播放時怎麼處理 strm 的內容，主要給其他工具產生的 strm（例如 alist 網址或本機路徑）。「進階設定」的欄位按頁面下方的「儲存設定」。見[播放與外網連線](播放與外網連線)。

| 鍵 | 預設值 | 說明 | 在網頁上改 |
| --- | --- | --- | --- |
| `resolve_redirects` | `false` | 先由伺服器跟著上游的重導向走到底，再把最終網址給播放器 | 進階設定 → 其他工具產生的 strm →「由伺服器先跟著上游的重導向走到底」 |
| `resolve_timeout` | `10.0` | 跟著重導向走時的逾時秒數 | 只能改檔案，要重新啟動 |
| `cache_ttl` | `90` | 走到的最終網址快取幾秒 | 只能改檔案 |
| `require_auth` | `true` | 播放網址是否要求登入，和官方 Emby 一樣。某個播放器播不了時再關 | 進階設定 → 其他工具產生的 strm →「播放網址要求登入」 |
| `default_container` | `mkv` | strm 看不出影片格式時的預設格式 | 進階設定 → 其他工具產生的 strm →「看不出格式時預設的影片格式」 |
| `path_rules` | `[]` | 把 strm 內容開頭的 `from` 換成 `to`，再 302 給播放器 | 進階設定 → 其他工具產生的 strm →「路徑替換」，一行一條 `原本開頭 => 替換成` |

```yaml
redirect:
  path_rules:
    - from: /mnt/115
      to: http://alist:5244/d/115
```

## api_keys

固定的 API 金鑰，給其他程式以管理員身分呼叫 Emby API，放在 `X-Emby-Token` 標頭或 `api_key` 查詢參數。

```yaml
api_keys:
  - 一串夠長的隨機字串
```

- 只能改檔案，改完重新整理管理網頁就生效，不必重新啟動。
- API 金鑰不能用來操作管理網頁（設定、備份、115 登入、帳號）。
- 在網頁「MoviePilot」分頁按「建立 API 金鑰」建立的金鑰存在資料庫，不會出現在這裡。一般用那個就好，見 [MoviePilot 整合](MoviePilot-整合)。
