第 2 步：選擇要產生 strm 的 115 目錄

115 目錄裡的影片會產生成 .strm 放到本機資料夾，目錄結構不變。本機資料夾要在某個媒體庫裡面，播放器才看得到；建議用媒體庫底下的子資料夾，例如 …/movies/115。

strm 內的伺服器位址：

增量：讀 115 的生活事件（操作紀錄），處理上次同步之後的上傳、移動、改名、刪除；移動和改名時，本機的 strm 連同刮好的 nfo、海報一起搬。再依修改時間補抓沒有產生事件的上傳（例如離線下載）。速度快，適合常常跑。
全量：重新比對整個目錄，查漏補缺，預設每週自動跑一次。
任務第一次增量同步、或太久沒同步超出 115 保留的事件範圍時，會自動改跑全量。

同步選項

Mi302 不自己刮削，而是交給 MoviePilot：同步產生新的 strm 後，請 MoviePilot 查影片資料，把 nfo 和海報寫到同一個資料夾，Mi302 再重新掃描。

連線設定
舊版 MoviePilot：改用帳號密碼

舊版的刮削 API 不接受 API 令牌，測試連線出現「拒絕存取」時再填。

MoviePilot 要能讀寫同一批 strm 檔案。兩個都用 Docker 時，把同一個主機資料夾掛進兩個容器；掛載路徑一樣就不用填對應。

刮削

把媒體庫裡還沒有 nfo 的影片送去 MoviePilot。已經有 nfo 的不會重送；劇集沒有 tvshow.nfo 時整部劇一起刮削。

讓 MoviePilot 把 Mi302 當成 Emby
