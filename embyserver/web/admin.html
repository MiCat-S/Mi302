增量和全量有什麼不同？

增量：讀 115 的生活事件（操作紀錄），處理上次同步之後的上傳、移動、改名、刪除；移動和改名時，本機的 strm 連同刮好的 nfo、海報一起搬。再依修改時間補抓沒有產生事件的上傳（例如離線下載）。速度快，適合常常跑。

全量：用 115 的「導出目錄樹」重新比對整個目錄，查漏補缺，預設每週自動跑一次。

任務第一次增量同步、或太久沒同步超出 115 保留的事件範圍時，會自動改跑全量。

媒體資訊

解析度、HDR、音軌、字幕軌和章節，播放器靠它標出 4K、HDR，播放前讓人選音軌和字幕。影片旁邊有 X-mediainfo.json（神醫助手、emby-mediainfo 產生的都行）就直接讀；開啟探測後，Mi302 用 ffprobe 讀 115 上的影片檔頭產生，每一項要取一次直鏈、讀幾 MB。

片頭片尾

從播放行為學：有人在開頭跳過一段、在片尾切下一集，就記成這一季的片頭片尾，播放器（Emby 系列、SenPlayer 等認 Emby 章節標記的，以及認 Jellyfin Intro Skipper 的）會顯示「跳過片頭」。不碰 115、不讀影片。同一季其他集自動套用，多人多集取中位數。學得不準或想先設好的，可以搜尋劇名、按「編輯」手動設定某一季（或標成沒有片頭）；手動設定的優先，不再照播放行為。

重複檔案

一次找兩種：「完全相同」是內容一模一樣（SHA1 一樣）的檔案；「不同版本」是同一部電影或同一集、檔案不同（例如 1080p 和 2160p）。刪除會送進 115 回收站，需要時可以在 115 還原；本機的 strm 跟著刪，觀看紀錄轉到保留的那份。

最近刪掉的

MoviePilot

Mi302 不自己刮削：同步產生新的 strm 後交給 MoviePilot 查影片資料，把 nfo 和海報寫到同一個資料夾，Mi302 再重新掃描。

連線

MoviePilot 帳號密碼（補全缺集、整理集號需要；舊版刮削 API 也需要）

「補全缺集」建訂閱的 API 只接受帳號登入。舊版的刮削 API 不接受 API 令牌，測試連線出現「拒絕存取」時也要填。

刮削

把媒體庫裡還沒有 nfo 的影片、以及有 nfo 卻沒有劇照的集送去 MoviePilot。劇集沒有 tvshow.nfo 時整部劇一起刮削；已經刮削過的劇會帶上 tmdbid，MoviePilot 不必再搜尋。

補全缺集

先向 MoviePilot 查 TMDB 上每一季已經播出的集（沒有播出日期、又在媒體庫最後一集之後的不算），對照 Mi302 裡已有的集號；真的缺集的季才建訂閱，並請 MoviePilot 馬上搜尋。已播出的都有就不建訂閱。要先把 Mi302 加成 MoviePilot 的媒體伺服器（見下方），並填上面的 MoviePilot 帳號密碼。

集號不對的劇：交給 MoviePilot 整理

這些集的集號不是從 nfo 讀到的（nfo 沒有集號，或刮削時沒認出來寫成 -1），檔名又不是 S01E02 這種標準寫法，是 Mi302 從「10.xxx」「第10集」這類寫法猜的，或根本認不出來。交給 MoviePilot 整理：它在 115 上把檔案改成自己命名設定的標準名稱（例如「劇名 - S01E10 - 集名」）並刮削，Mi302 再同步過來。會真的改 115 上的檔名和位置，所以一定先預覽，看過每個檔案的新路徑再執行。需要 MoviePilot v2.11.1-1 以上（更舊的不支援預覽）和上面的 MoviePilot 帳號密碼（要是管理員），MoviePilot 的 115 網盤也要登入同一個帳號。
